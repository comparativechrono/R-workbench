Four ways to use R

≈ 10 min

R is a language and a program. How you talk to it – a console, an editor, a document, a command – changes what you can do with it.

What is here

The workbench on the right has R in four forms. They are all the same R – R 4.6, running in your browser – but each is a different way of working with it, and each has its place:

R consoleType a command, see the answer. R as it comes – quick, and nothing is kept but the history.
RStudioScripts you edit, run and keep, with the environment, plots, help and files around them.
Documents and notebooksText, code and results together: R Markdown, Quarto, R Notebooks and Jupyter.
TerminalRscript and R CMD BATCH: R with no window at all, run by commands.

In this practical you do a little of the same work in each of them, so that you can see what each way is good for – and what it leaves out. The data are measurements of 344 penguins from three islands of the Palmer Archipelago in Antarctica: you find them in your files as ~/data/penguins.csv (and penguins.xlsx), and R 4.6 has them built in, as penguins.

How this page works

  • The instructions are on the left, the workbench on the right. The tabs at the top of the workbench switch between the ways of using R; Files shows your files, and AI is an AI assistant you can ask about R.
  • The steps of an activity tick themselves when you do them (✓ spotted) – you can also tick them yourself. Buttons such as type the code for you; you press Enter.
  • Your answers and your files are kept in this browser, on this computer. My answers downloads your answers; My files downloads all your files as a .zip file. Download them before you clear the browser or move to another computer.
  • The first time a tab with R is opened, R is downloaded (about 30 MB) – that takes a moment. Packages you install are downloaded once, too.
Every R here is an R of its own

As on your own computer, the R console, RStudio, the notebook and each run in the terminal are separate R sessions: an object you make in one is not in another. What they share is your files – the same home folder, ~ – and the packages you install.

R's own console

≈ 15 min

Type, see the answer, move on: the quickest way to talk to R – and the one that keeps least.

The R console tab is R as it comes when you install it on a computer: one window, R's console, where you type a command after the prompt > and R answers under it. Plots, help pages and data open in windows of their own.

Talking to R

Commands and objects
  1. Type x <- c(3, 8, 1) – nothing is printed: R made an object, x. Then mean(x) .
  2. Press ↑ to bring back mean(x), change it to median(x) and press Enter.
  3. Type sum(x – with the closing bracket missing – and press Enter. R shows +: it waits for the rest of the command. Type ) and Enter.
Assignment and printing

x <- value makes (or replaces) an object called x, and prints nothing. A command that is not an assignment prints its result: [1] marks the first value of the result. Esc stops what R is doing – and gets you out of a + you did not mean.

The penguins

Look at the data
  1. head(penguins) prints the first six penguins; summary(penguins$body_mass) summarises one column.
  2. View(penguins) opens the data in a window of their own: sort by a column, search.
  3. plot(body_mass ~ flipper_len, data = penguins) draws a plot in a graphics window. Move the window, resize it.
  4. ?mean opens R’s help for mean. Read what na.rm does.
mean(penguins$body_mass) gives NA. Why, and how do you get the mean of the masses that were measured?
Two of the penguins have no body mass (NA, a missing value), and the mean of anything with a missing value is unknown. mean(penguins$body_mass, na.rm = TRUE) leaves the missing values out: about 4202 g.

Quitting – and what is kept

When you quit R, everything in its memory – the workspace – goes, unless you save it.

Save the workspace
  1. Type q() . R asks Save workspace image? [y/n/c]: – answer y.
  2. Click Start R again in the console. R says [Previously saved workspace restored].
  3. Type x – your object is back. R saved it in the file ~/.RData, and loads that file when it starts.
You made x, quit R without saving the workspace, and started R again. What does x give?
What is the console good for? And when you come back next week, what does it not tell you about how you got your results?
Good for: trying things quickly, checking a value, reading help – an answer straight away. It does not keep a tidy record: the history has every line you typed, mistakes included, and the saved workspace has objects without the commands that made them. Next week you have results you cannot easily make again.

Scripts in RStudio

≈ 20 min

Write your commands in a script, run them as you go – and keep a record that makes your results again.

RStudio is an integrated development environment (IDE) for R: around R's console it puts an editor for your scripts and documents (Source, top left), what is in R's memory (Environment), and your files, plots, packages, help and a viewer for web pages. The RStudio tab of the workbench works as RStudio does.

An R of its own

RStudio's Console is another R: x from the R console tab is not there. Everything you run in RStudio – a line, a chunk, a whole script – runs in this one R, the one its Console shows.

A script

A script is a text file of R commands, .R. You write it, run it a line at a time while you work it out – and keep it.

scripts/penguins.R
# Penguins: body mass by species
penguins <- read.csv("data/penguins.csv")
str(penguins)

# the mean body mass of each species (missing masses left out)
mass <- aggregate(body_mass ~ species, data = penguins, FUN = mean)
mass

boxplot(body_mass ~ species, data = penguins,
        ylab = "Body mass (g)", col = "lightblue")
Create this file saves it in your files and opens it in RStudio's Source pane.
Run a script, line by line
  1. Click Create this file above. The script opens in RStudio.
  2. Put the cursor on the line with read.csv and press Ctrl+Enter (on a Mac ⌘+Enter): the line goes to the Console, and penguins appears in the Environment.
  3. Go on with Ctrl+Enter to the end. A statement over several lines – boxplot( – runs as one. The plot is in the Plots pane.
  4. In the Environment, click the ▶ next to penguins to see its columns, and the table icon to view it.

The script is the record

Restarting R empties its memory. With a script, that does not matter: run it again, and everything is back – made in the same way.

Start again from the script
  1. Session ▸ Restart R (Ctrl+Shift+F10). The Environment is empty.
  2. Click Source at the top of the script: RStudio runs source("~/scripts/penguins.R") – the whole script, in one go.
  3. Add a line at the end of the script that counts the penguins of each species, table(penguins$species). Save the script (Ctrl+S) and run the new line.
Code that writes code

RStudio's Import Dataset (in the Environment pane) reads a file through a dialog – and shows the R code it runs. Copy that code into your script: then the import is part of the record too.

Import a dataset
  1. Environment ▸ Import Dataset ▸ From Excel…, Browse to data/penguins.xlsx. Look at the preview and the code – then Import (the first time, RStudio installs the readxl package).
You have a script and a saved workspace (.RData). A colleague finds a mistake in the data file, and you correct it. Which of the two gives you corrected results – and why?
The script: run it again and every result is made afresh from the corrected file. The saved workspace holds the old results, and nothing in it says how they were made. (This is why RStudio can be set not to save or restore .RData at all: Tools ▸ Global Options.)

If you have time: an app

RStudio also runs Shiny apps – web pages made in R, whose inputs (a slider, a menu) change what R computes and draws. File ▸ New File ▸ Shiny Web App… makes one in a folder of its own; Run App starts it in the Viewer. The Console is busy while the app runs: Stop (or Esc) ends it.

Documents: R Markdown and Quarto

≈ 20 min

Text, code and results in one document – made again, from the top, every time you knit it.

A report has text, code and results: tables, plots, numbers in sentences. In an R Markdown document (.Rmd) – or its successor Quarto (.qmd) – they are written together: text in Markdown, code in chunks. Knitting runs the code and makes the whole into a web page (or, on a computer with the programs for it, a PDF or Word document).

An R Markdown document

Write and knit a report
  1. In RStudio: File ▸ New File ▸ R Markdown…. Title: Penguin report, your name as the author, HTML – OK.
  2. Save it (Ctrl+S) as reports/penguins.Rmd – type reports/penguins.Rmd as the file name.
  3. Run a chunk with its green ▶: its output appears under the chunk, in the document.
  4. Click Knit. The first time, RStudio installs knitr and markdown. The report opens in the Viewer – and is saved as reports/penguins.html.
Knitting starts from nothing

Knit runs the document in a new R, from the top – not in the R of RStudio's Console. Whatever the report needs, it must make or read itself. That is what makes a knitted report trustworthy: it shows that the code, as written, gives these results.

Break it, on purpose
  1. In RStudio’s Console, make an object penguin_colours: .
  2. Add a chunk to the report (the +C button, or Ctrl+Alt+I) with barplot(table(penguins$species), col = penguin_colours). Run the chunk with ▶ – it works.
  3. Now Knit. It stops: object 'penguin_colours' not found (see Background Jobs). Fix the report so that it makes penguin_colours itself, and knit again.
Running the chunk with ▶ worked, knitting failed. Explain the difference.
▶ runs the chunk in the R of RStudio's Console, where penguin_colours had been made by hand. Knit runs the whole document in a new, empty R: penguin_colours exists there only if the document makes it. A report that knits contains everything needed to make its results.

R Notebooks and Quarto

An R Notebook is an R Markdown document that you run chunk by chunk, as you work; when you save it, a web page with the text, the code and the outputs as they are is saved next to it (.nb.html) – nothing is run again. Quarto documents are written like R Markdown and Render like Knit; Quarto also works with Python and Julia.

Try them
  1. File ▸ New File ▸ R Notebook. Run its chunk, save it as reports/notes.Rmd, and click Preview.
  2. File ▸ New File ▸ Quarto Document… – Create, save it as reports/quarto.qmd and Render it.
You ran the chunks of an R Notebook in the order 3, 1, 2 and saved it. What does its .nb.html show?

Jupyter notebooks

≈ 15 min

Cells of code with their output, kept in one file – easy to share, easy to run out of order.

A Jupyter notebook (.ipynb) is a list of cells: code cells, whose output appears under them, and text cells in Markdown. Jupyter started with Python; with an R kernel – as here – the code is R. The notebook file keeps the outputs, so it can be shared and read without running anything: on GitHub, in JupyterLab, VS Code or Google Colab.

Yet another R

The notebook's R is separate from the R console's and RStudio's. All notebooks here share one R – and it starts in the notebook's folder.

Cells

Run cells
  1. Open the Notebook tab . A new notebook is there, in ~/notebooks.
  2. In the first code cell type head(penguins) and press Shift+Enter: the data appear as a table. The number in [1] says this was the first cell R ran.
  3. In the next cell: hist(penguins$flipper_len, main = "Flipper length", xlab = "mm"), Shift+Enter.
  4. Add a text cell (+ Text) with a sentence about what the histogram shows. Shift+Enter shows it as text.

Out of order

Cells can be run in any order, and a cell can be changed after it ran. Its output then belongs to code that is no longer there.

Hidden state
  1. Make a cell with n <- 10 and run it; below it a cell with n * 2 – run it: 20.
  2. Change the first cell to n <- 1000, but do not run it. Run only the n * 2 cell: still 20 – the notebook now shows code and a result that do not match.
  3. Kernel menu (the R button at the top) ▸ Restart R and run all cells: every cell runs again, from the top, in a new R.
  4. Download ▸ the notebook (.ipynb): it opens in Jupyter, JupyterLab, VS Code or Colab with its outputs.
What is the danger of running a notebook's cells out of order – and what is the habit that protects you from it?
The outputs on the page may not come from the code on the page: a cell's result depends on whatever ran before it, in any order, including cells since changed or deleted. Habit: before you share or trust a notebook, restart R and run all cells from the top (Restart & run all) – the same check that knitting does for an R Markdown document.
An R Markdown document (.Rmd) and a Jupyter notebook (.ipynb) can both hold text, code and results. Name one practical difference between the files.
A .Rmd file is plain text with no outputs in it: easy to read, compare and keep in version control (Git), and the results come from knitting. An .ipynb file is JSON with the outputs inside (plots as long strings of base64): it shows results without running, but differences between versions are hard to read.

R without a window

≈ 15 min

Rscript, R CMD BATCH and R: R started by a command – for servers, clusters, pipelines and anything you run many times.

R does not need a window. On servers and computing clusters – where long analyses run – there is no screen: R is started by a command, runs a script and ends. The Terminal tab is a Linux terminal (bash) with R's commands: Rscript and R CMD BATCH run scripts, and R starts R's console in the terminal.

Rscript

Run your script
  1. Open the Terminal . Type ls scripts – the script from RStudio is there: the files are the same everywhere.
  2. Run it: Rscript scripts/penguins.R . What it prints comes here; the plot has nowhere to go, so R puts it into Rplots.pdf (ls -l Rplots.pdf ).
scripts/count.R
# How many penguins of a species? The species comes from the command line:
#   Rscript scripts/count.R Gentoo
args <- commandArgs(trailingOnly = TRUE)
species <- if (length(args) > 0) args[1] else "Adelie"

penguins <- read.csv("data/penguins.csv")
n <- sum(penguins$species == species)
cat(species, ":", n, "penguins\n")
This script reads the species from its command line, with commandArgs().
Scripts that take arguments
  1. Create scripts/count.R (the button above).
  2. Rscript scripts/count.R Gentoo – then with Chinstrap.
  3. All three species with one line of bash: for s in Adelie Chinstrap Gentoo; do Rscript scripts/count.R $s; done
  4. An error stops a script, and the exit status says so: Rscript -e 'mean(no_such_thing)'; echo "exit status: $?"
Exit status

Every program tells the shell how it ended: 0 for success, anything else for failure ($? holds it). A pipeline of scripts can stop at the first failure (set -e) – instead of carrying on with results that were never made.

R CMD BATCH and R

A record of the run
  1. R CMD BATCH scripts/penguins.R prints nothing: everything – the commands, their output, how long it took – goes into penguins.Rout. Look: cat penguins.Rout .
  2. R -q starts R’s console in the terminal. Try summary(penguins$bill_len), then q().
Give two situations in which you would run R with Rscript rather than in RStudio.
For example: on a server or a computing cluster with no screen (a job submitted to a queue); a long analysis that runs overnight; the same script for many inputs (a loop over files or species); a step in a pipeline or a scheduled job that runs without anyone there; checking that a script runs on its own, from the top, in a fresh R.

Which way, when?

≈ 10 min

The same R, five ways to work with it – and how they fit together.

Each way of using R keeps something different, and suits a different job. In practice you will move between them: try a command in the console, put it in a script, knit the analysis into a report, run it on a server with Rscript.

WayWhat is keptGood for
R consolenothing – only the history and, if saved, a workspacetrying things, quick checks, help
Script in RStudiothe script: the commands that make the resultsanalyses you will run again; most of your work
R Markdown / Quartoa document that makes its results when knittedreports, papers, theses; sharing methods with results
Jupyter notebookcode with the outputs of the last runsexploring and showing; teaching; mixing languages
Rscript / R CMD BATCHthe script; a log of the run (.Rout); output filesservers, clusters, pipelines, scheduled and repeated runs
You are starting a project: the analysis of a lab's measurements, written up as a report for your supervisor, run again when new measurements come in. Which ways of using R would you use, and for what?
For example: the console to look at the data and try things; the analysis in R scripts (in RStudio) or directly in an R Markdown/Quarto report, so that the report is made again from the data each time it is knitted; possibly Rscript to re-run the analysis automatically when new data arrive. A notebook could serve for exploring – restarted and run from the top before anything is shared.
